One page, three ways to write it.

Text with braces, indented markup, or Markdown, over one expression language. A template compiles once and renders as often as you like; it touches no file, clock or socket unless you hand it a function that does.

Blocks in any language
Switch language anywhere with {% block lang=pug %}. Blocks nest; force keeps a stretch to its own language.

    
Escaped unless trusted
Output is escaped by default. |safe and markup values pass through; filters that build markup escape what they wrap.

    
Compile once
Env keeps compiled templates by name; Template::render takes any ToJson value.

    
Host objects
Implement Object and a value of yours has attributes, calls, loops and assignments in a template.

    
Your own language
Register a reader with a name and aliases; the three built in go through the same door.

    
Refusals with a place
Every error names the template and line, and the column when the source is malformed. Deep recursion is refused, not overflowed.

Start

        
struct Book { title : String; year : Int } derive(ToJson)
struct Shelf { shelf : String; books : Array[Book] } derive(ToJson)

let page = "<h1>{{ shelf }}</h1>{% for b in books %}<p>{{ b.title }}</p>{% endfor %}"
let html = @moonpug.render(page, Shelf::{ shelf: "Reading <list>", books })
// <h1>Reading &lt;list&gt;</h1><p>…</p>

        
Data goes in as anything that converts to Json. render compiles and renders in one call; an Env keeps compiled templates when the same one renders again.

A named template picks its format from the extension: .pug and .pg read as pug, .md as Markdown, .html, .htm, .xml and .svg as escaped HTML, anything else as text.

      


      

        
Language blocks

        
<section>
{% block lang=pug %}
ul
  each i in items
    li= i
{% endblock %}
</section>

        
A whole template is one block in its own language, and blocks inside it may switch again, as deep as they like. With force=true a stretch reads only its own language: inside pug and Markdown, blocks in another language stay as text and HTML still reads; inside HTML, pug and Markdown blocks stay as text. A block's own force= wins over the one around it.

      


      

        
Writing templates

        
Statements

        
if, for with loop and else, break, continue, set, with, macro and call, filter, include, import, extends and block with super(), raw, autoescape, do, trans, once, show, debug.

        
Expressions

        
Literals, lists, tuples and maps; attributes, subscripts and slices; arithmetic with //, % and **; comparisons that chain; in, and, or, not; ~ to join as text; inline if; filters with | and tests with is. Strings, lists and maps carry their methods: '{:>8.2f}'.format(x), '%s=%d' % (k, v), d.items().

        
In pug

        
Tags with #id and .class; attributes in ( ), or [ ] and { } when a long list wraps; &attributes; #{} and !{}; #[tag] inline; | and . text; if, unless, each, case with when a, b; mixins with blocks; include with a block that lands at yield; extends with block append and prepend; doctype; :name content filters.

      


      

        
Data and objects

        
let env = @moonpug.Env::new()
env.add_global("today", @moonpug.Value::func("today", (_, _, _) => Text("2026-10-25")))
env.add_filter("money", (call, value, _, _) => Text("¥" + call.text(value)))

impl @moonpug.Object for Cart with fn kind(_) { "the cart" }
impl @moonpug.Object for Cart with fn attr(self, name) { … }   // cart.total
impl @moonpug.Object for Cart with fn items(self) { … }        // for x in cart

env.compile(source).render_values({ "cart": Object(cart) })

        
Object has kind, attr, call, callable, assign, show and items; every one but kind has a default.

      


      

        
Templates by name

        
let env = @moonpug.Env::new(load=name => sources.get(name))
let page = env.template("page.html")   // read, compiled and kept
page.render(data)

        
load serves extends, include and import. translate answers trans and gettext with a message, its context and the plural count. cache stores what once renders. All three are functions you pass in.

      


      

        
Your own language

        
fn read_csv(source : String, reading : @moonpug.Reading) -> Array[@syntax.Node] raise @moonpug.Refused {
  …
  nodes.append(reading.block(cell, "html", None, reading.line))
  …
}

env.add_lang({ name: "csv", aliases: ["table"], options: @syntax.options, read: read_csv })

        
Then {% block lang=csv %} and Format.lang = "csv" both work. moonbitstack/moonpug/syntax has the tree and the parsers for expressions and statements, for a reader to reuse.
